# MP-109 two-client ladder test on Windows

Build a small deathmatch map with one ladder and one stalker, then watch the same bot from two game windows on the same PC. This test uses engine commit `6269279ce070ca0d775d37711d49a270e8392b2c`. The Windows build and gameplay checks are pending.

Use PowerShell 7.4 or newer in your Windows repo checkout with the MP-109 changes. Reuse the Visual Studio, x64 CMake, and game assets from your passing W0 run. If the candidate is only on your Mac, [copy it to Windows first](#if-the-commit-is-only-on-your-mac). The first build and asset copy can take a while. Once the runner starts the game, it gives the server two minutes to become ready and the clients three minutes to join.

## 1. Set up the IX-Ray Level Editor workspace

### Set the folder paths

Use IX-Ray’s Level Editor and compilers with the file-system settings from this checkout. To build the arena, you also need editable level objects in `rawdata\objects`. The repo ships an editor axis in that folder. The retail game archives supply compiled game assets. The main route below reconstructs a stock map from your game copy for editing in IX-Ray.

From your Windows repo checkout, set the three paths below. Use your original Call of Pripyat installation or the IX-Ray game folder from W0 for `$Original`. Pick new folders for the test game copy (`$GameRoot`) and editor workspace (`$Sdk`). Use a short, ASCII-only path for `$Sdk` so the older converter can read it.

~~~powershell
$Candidate = '6269279ce070ca0d775d37711d49a270e8392b2c'
$Checkout = (Get-Location).Path
$Original = 'C:\Games\Call of Pripyat'
$GameRoot = 'C:\Games\IXRay-MP109'
$Sdk = 'C:\Games\IXRay-MP109-Editor'
$Map = 'mp109_ladder'
$Runner = '.\scripts\multiplayer\windows\RunCheckpoint.ps1'

git cat-file -e "$Candidate^{commit}"
if ($LASTEXITCODE -ne 0) { throw 'Sync the MP-109 commit into this Windows checkout, then retry.' }
~~~

~~~powershell
if (Test-Path -LiteralPath $GameRoot) { throw 'Use a new path for the MP-109 game copy.' }
~~~

### Build or locate the IX-Ray tools

If your IX-Ray build already contains `LevelEditor.exe`, `xrLevelBuilder.exe`, `xrSE_Factory.dll`, and `xrCompress.exe` together, set `$Tools = 'C:\path\to\bin\RelWithDebInfo'` to that folder. Otherwise, build the tools from this checkout.

### Reconstruct a stock map from your game files

Use these steps with the `$GameRoot` copy from above. `xrCompress` unpacks the mounted game archives into `$Sdk\gamedata`, including the retail MP maps and their materials. Allow room for the unpacked game data. [IX-Ray unpacker reference](../../docs/main/en/utilities/compressor.md)

~~~powershell
$UnpackedGameData = Join-Path $Sdk 'gamedata'
$ReconstructionLogs = Join-Path $Sdk 'mp109-reconstruction'
if (Test-Path -LiteralPath $UnpackedGameData) { throw 'Use a fresh editor workspace for unpacking.' }
$null = New-Item -ItemType Directory -Path $UnpackedGameData, $ReconstructionLogs -Force
$UnpackLog = Join-Path $ReconstructionLogs 'xrcompress.log'
Copy-Item -LiteralPath (Join-Path $Checkout 'fsgame.ltx') -Destination (Join-Path $GameRoot 'mp109-unpack.ltx') -ErrorAction Stop

Push-Location $GameRoot
try {
    & (Join-Path $Tools 'xrCompress.exe') -unpack mp109-unpack.ltx $UnpackedGameData *> $UnpackLog
    if ($LASTEXITCODE -ne 0) { throw "Game unpacking failed. See $UnpackLog." }
} finally {
    Pop-Location
}

$StockLevels = Join-Path $UnpackedGameData 'levels'
foreach ($Path in 'gamemtl.xr', 'shaders_xrlc.xr', 'levels') {
    if (!(Test-Path -LiteralPath (Join-Path $UnpackedGameData $Path))) {
        throw "Missing $Path after unpacking. See $UnpackLog."
    }
}
$StockMaps = @(Get-ChildItem -LiteralPath $StockLevels -Directory -Filter 'mp_*' |
    Where-Object { Test-Path -LiteralPath (Join-Path $_.FullName 'level') -PathType Leaf })
if (!$StockMaps.Count) { throw "No stock MP levels found. Check the game copy's mp archives and $UnpackLog." }
$StockMaps | Select-Object -ExpandProperty Name
~~~

Pick a small MP map from the printed list. The example uses `mp_atp` if it appears. Replace it with the exact map folder name if you choose another. Use the pinned `xray_re-tools 0.3.1` archive for scene reconstruction. From the same PowerShell window, download and configure the converter. This sets the CoP profile to the unpacked files and the converter’s output root to `$Sdk`. [xray_re-tools release and bundled converter reference](https://github.com/abramcumner/xray_re-tools/releases/tag/0.3.1), [standalone 7-Zip](https://www.7-zip.org/download.html)

~~~powershell
$FromMap = 'mp_atp'
if ($FromMap -notin $StockMaps.Name) { throw 'Set $FromMap to one of the stock maps listed above.' }
$SceneName = 'mp109_stock_source'
$ConverterDir = Join-Path $Sdk 'mp109-converter'
$null = New-Item -ItemType Directory -Path $ConverterDir -Force
$ConverterArchive = Join-Path $ConverterDir 'xray_re-tools_0.3.1_x86.7z'
$SevenZip = Join-Path $ConverterDir '7zr.exe'
Invoke-WebRequest -Uri 'https://github.com/abramcumner/xray_re-tools/releases/download/0.3.1/xray_re-tools_0.3.1_x86.7z' -OutFile $ConverterArchive -ErrorAction Stop
Invoke-WebRequest -Uri 'https://github.com/ip7z/7zip/releases/download/26.06/7zr.exe' -OutFile $SevenZip -ErrorAction Stop
& $SevenZip x $ConverterArchive "-o$ConverterDir" -y
if ($LASTEXITCODE -ne 0) { throw 'Could not unpack xray_re-tools.' }

$Latin1 = [Text.Encoding]::Latin1
$FsTemplate = [IO.File]::ReadAllText((Join-Path $ConverterDir 'fsconverter_cop.ltx'), $Latin1)
$FsPath = Join-Path $ConverterDir 'fsconverter.ltx'
$SdkRoot = $Sdk.TrimEnd('\') + '\'
[IO.File]::WriteAllText($FsPath, $FsTemplate.Replace('c:\program files\X-Ray CoP SDK\editors\', $SdkRoot), $Latin1)

$IniPath = Join-Path $ConverterDir 'converter.ini'
$Ini = [IO.File]::ReadAllText($IniPath, $Latin1)
$DataRoot = $UnpackedGameData.TrimEnd('\') + '\'
[IO.File]::WriteAllText($IniPath, $Ini.Replace('E:\Games\COP\gamedata\', $DataRoot), $Latin1)
Copy-Item -LiteralPath $FsPath, $IniPath -Destination $ReconstructionLogs -ErrorAction Stop
~~~

First run the converter’s read-only check, then write the scene. If you retry the conversion, give `$SceneName` a fresh name to keep the old scene and its objects.

~~~powershell
$SceneFile = Join-Path $Sdk "rawdata\levels\$SceneName.level"
$SceneParts = Join-Path $Sdk "rawdata\levels\$SceneName"
$SceneObjects = Join-Path $Sdk "rawdata\objects\levels\$SceneName"
if ((Test-Path -LiteralPath $SceneFile) -or (Test-Path -LiteralPath $SceneParts) -or
    (Test-Path -LiteralPath $SceneObjects)) {
    throw 'Use a fresh $SceneName for this conversion.'
}
$DryLog = Join-Path $ReconstructionLogs 'converter-dry-run.log'
$ConvertLog = Join-Path $ReconstructionLogs 'converter.log'
$ConvertArgs = @('-level', "cop:$FromMap", '-out', $SceneName, '-mode', 'le', '-with_lods')
Push-Location $ConverterDir
try {
    & .\converter.exe -ro @ConvertArgs *> $DryLog
    if ($LASTEXITCODE -ne 0 -or !(Select-String -LiteralPath $DryLog -SimpleMatch 'saving scene' -Quiet)) {
        throw "Converter dry run did not reach the scene output step. See $DryLog."
    }
    & .\converter.exe @ConvertArgs *> $ConvertLog
    $ConvertExit = $LASTEXITCODE
    $FirstObject = Get-ChildItem -LiteralPath $SceneObjects -Filter '*.object' -File -Recurse -ErrorAction SilentlyContinue |
        Where-Object Length -GT 0 | Select-Object -First 1
    if ($ConvertExit -ne 0 -or !(Test-Path -LiteralPath $SceneFile -PathType Leaf) -or
        !(Test-Path -LiteralPath $SceneParts -PathType Container) -or !$FirstObject) {
        throw "Scene or object library is missing. See $ConvertLog."
    }
} finally {
    Pop-Location
}
$AssetSource = $Sdk
$SceneFile
~~~

Expect `$Sdk\rawdata\levels\mp109_stock_source.level` and the object folder `$Sdk\rawdata\objects\levels\mp109_stock_source`. Proceed to [Prepare the IX-Ray workspace](#prepare-the-ix-ray-workspace). The converter commands and settings were checked against the pinned release. Conversion and rebaking with a stock map in the Windows editor still need a live run.

### Prepare the IX-Ray workspace

Run this from the same checkout. It adds the repo’s editor resources and file-system settings to the reconstructed workspace. If you chose a separate asset source, it copies in that library first.

~~~powershell
foreach ($Path in 'gamedata/gamemtl.xr', 'rawdata/objects') {
    if (!(Test-Path -LiteralPath (Join-Path $AssetSource $Path))) {
        throw "Missing $Path under $AssetSource."
    }
}
$null = New-Item -ItemType Directory -Path $Sdk -Force
foreach ($Folder in 'gamedata', 'rawdata') {
    $Destination = Join-Path $Sdk $Folder
    if ($AssetSource -ne $Sdk) {
        robocopy (Join-Path $AssetSource $Folder) $Destination /E /XJ /R:0 /W:0 /NFL /NDL /NP

    }

    if ($LASTEXITCODE -ge 8) { throw "Could not copy the IX-Ray $Folder to $Sdk." }
}
Copy-Item -LiteralPath '.\fs.ltx', '.\fsfactory.ltx', '.\fsgame.ltx', '.\.xrignore' -Destination $Sdk -Force -ErrorAction Stop
~~~

## 2. Build one ladder arena

1. In **Scene Properties**, set **Build options → Level path** to `mp109_ladder` and **Map version** to `1.0`. Enable **deathmatch** under **Game Type**.
2. Keep or add a lower floor, a raised platform, and one tall ladder. Remove extra climbable faces from the scene so the test bake produces one ladder. In **Objects → Library Editor**, check that the ladder face’s **Game Mtl** has **Flags → Climable**. Leave the face and both landings clear. The tall ladder gives you time to reconnect during a climb. In an empty scene, add an outdoor light and use **Sector → Create Default**.
3. Keep or add two `$rpoint` markers on clear lower ground several metres apart. For both, choose **Actor Spawn**, **Team 0**, and **deathmatch**. Add one **Spawn → stalkers → stalker** on clear lower ground and enable **deathmatch** for it.
4. In **AI Map**, use **Clear AI Map** to remove any imported grid before generating the test grid. Select the floor and platform objects. Use **Snap List → Make List From Selected**. In **AI Map**, place a seed on each floor and click **Generate Full**. Check that each landing has a patch of connected nodes. Keep the floors disconnected so the ladder is the bot’s only route between them.
5. Save the scene. Choose **Compile → Make → Make All**. In `$Sdk\gamedata\levels\mp109_ladder`, check for `build.prj`, `build.aimap`, `level.game`, and `level.spawn`. **Make Game** exports the player spawns, ladder, and stalker. **Make AI-Map (25 bit)** exports the editor grid.

Launch the compiler from the same PowerShell window.

~~~powershell
Start-Process -FilePath (Join-Path $Tools 'xrLevelBuilder.exe') -WorkingDirectory $Sdk -ArgumentList '-fsltx fsgame.ltx'
~~~

Select only `mp109_ladder` in the compiler. Enable **Lighting Compiler** and click **Run Compiler**. When it finishes, switch off **Lighting Compiler**, enable **AI Compiler**, and check **AI Compiler ai.level** and **Verify**. Leave **Draft AI-Map** and **AI Compiler all.spawn** off. Click **Run Compiler** again. Check that `level.ai` and `level.cform` are in the same folder as `level.spawn`.

Write down the two numbers after `nodes=` in `w1-ladders.txt`. The lower node comes first. If you rebake, move the previous staged map folder out of `gamedata\levels` before staging the new one. Keep the old report with it.

Expect `w1_navigation_passed`. Copy the full path printed after `W0 report`. If the runner fails, send that `report.json` and its entire neighbouring `logs` folder. The startup check covers joins and navigation readiness. The next steps check the stalker.

## 4. Start the interactive server and two clients

Open two PowerShell windows. In **both**, paste this block with your W1 report path.

~~~powershell
$W1Report = 'C:\path\from\W0-report\report.json'
$Run = Get-Content -LiteralPath $W1Report -Raw | ConvertFrom-Json
if ($Run.status -ne 'w1_navigation_passed' -or $Run.actualRevision -ne '6269279ce070ca0d775d37711d49a270e8392b2c') {
    throw 'Use the passing W1 report for the MP-109 candidate.'
}
$Runtime = Join-Path $Run.workspaceDirectory 'runtime'
$Bin = Join-Path $Run.buildDirectory "bin/$($Run.configuration)"
$Map = $Run.runtime.map
$Port = $Run.runtime.port
$Tag = 'mp109'
~~~

In the **first** window, run this block. Keep the printed `start server(...) client(...)` line for the reload test. Wait for `Arena navigation` with `links=2` and `DM ready: role=server`.

~~~powershell
$Server = "server($Map/deathmatch/maxplayers=32/portsv=$Port/public=0/bots=1)"
$InternalClient = "client(localhost/port=$Port/name=MP109Server)"
Write-Host "start $Server $InternalClient"
Push-Location $Runtime
try {
    $null = New-Item -ItemType Directory -Path "$Tag-server" -ErrorAction Stop
    & (Join-Path $Bin 'xrServerCLI.exe') -overlaypath "$Tag-server" -nosound -mp_route_trace -start $Server $InternalClient
} finally {
    Pop-Location
}
~~~

In the **second** window, run this block. It prints the exact reconnect command for each client. Arrange the two game windows side by side. Press **Space** in each to enter play. The backtick key opens the game console.

~~~powershell
foreach ($Index in 1, 2) {
    $Overlay = "$Tag-client-$Index"
    $Data = New-Item -ItemType Directory -Path (Join-Path $Runtime $Overlay) -ErrorAction Stop
    'rs_fullscreen 0' | Set-Content -LiteralPath (Join-Path $Data.FullName 'user.ltx') -Encoding ascii
    $Connect = "client(127.0.0.1/port=$Port/name=MP109Client$Index)"
    Start-Process -FilePath (Join-Path $Bin 'xrEngine.exe') -WorkingDirectory $Runtime -ArgumentList @(
        '-overlaypath', $Overlay, '-nosound', '-r2', '-mp_route_trace', '-start', $Connect
    )
    Write-Host "Client $Index reconnect command is start $Connect"
}
~~~

For another attempt using the same W1 report, use a new `$Tag` in both windows, such as `mp109-retry`. If the port was taken after W1 exited, set `$Port` to the same available local UDP port in both windows.

## 5. Move the bot and record what you see

Paste these lines one at a time into the **dedicated server console**. In the second line, replace `12` and `84` with your lower and upper node IDs. The first line prints the bot ID. If it reports no live stalker, save the dedicated log and check the stalker spawn and deathmatch flag in the editor.

~~~text
run_string mp109_bot=nil; for i=0,65534 do local n=level.object_by_id(i); if n and n:section()=="stalker" and n:alive() then mp109_bot=i; break end end; assert(mp109_bot,"MP109 no live stalker"); log1("MP109 stalker="..mp109_bot)
run_string mp109_lower=12; mp109_upper=84; assert(level.valid_vertex_id(mp109_lower) and level.valid_vertex_id(mp109_upper))
run_string function mp109_go(v) local n=assert(level.object_by_id(mp109_bot)); assert(n:alive()); if not n:get_script() then n:script(true,"mp109") end; assert(n:get_script_name()=="mp109"); n:reset_action_queue(); log1("MP109 goal="..v.." stalker="..mp109_bot); action(n,move(move.standing,move.walk,move.line,level.vertex_position(v)),cond(cond.move_end)) end
~~~

Give the bot the lower goal first. Once it arrives, give it the upper goal. After it dismounts at the top, send it back down.

~~~text
run_string mp109_go(mp109_lower)
run_string mp109_go(mp109_upper)
run_string mp109_go(mp109_lower)
~~~

Record both windows together or save a clip from each. Write `pass`, `fail`, or `skip` for each check in `observations.txt`. Add a short note for anything that failed or was skipped.

| Check | What to do and watch for |
| --- | --- |
| Up and down | Watch one full trip each way. The bot faces the ladder, mounts, moves its hands and feet with the climb, and returns to a normal pose on the correct floor. Both client logs should show `up` or `down` and then `ground` for the same stalker. |
| Blocked exit | Move client 2 to the upper floor and stand in the ladder exit. Send the bot up while client 1 watches. The pose should hold when the body stops. If the dedicated log reports `failed`, both clients should leave the climb pose. Move client 2 clear and watch the next attempt. |
| Late join | On client 2 enter `disconnect`. Send the bot to the other floor. While client 1 sees it climbing, paste client 2’s printed reconnect command into its game console. The bot should first appear in its current position and phase. Repeat in the other direction. If the climb ends before client 2 sees it, retry or mark the case skipped. |
| Death during a climb | While both clients are watching a climb, paste the kill command below into the dedicated console. Both clients should switch from climb to death. |
| Reload during a climb | Reload after the death check to get a live bot. Start another climb and reload while it is on the ladder. Reconnect both clients, paste the three setup lines again, and verify that the new bot starts normally and can climb. The dedicated log should show the old navigation generation closing and a new one becoming ready. |

Kill the selected bot from the dedicated server console.

~~~text
run_string local n=assert(level.object_by_id(mp109_bot)); n:kill(n)
~~~

To reload, enter `disconnect` in the **dedicated** console, then paste the `start server(...) client(...)` line printed in the first PowerShell window. After `DM ready: role=server`, use the respective reconnect commands in the two game consoles. When finished, type `quit` in each game console and the dedicated console so all three logs close.

## If the material file is still in an archive

Use the SDK file-system configuration to unpack to a scratch folder. In step 3, set `$Materials` to the extracted file shown below.

~~~powershell
$Unpacked = Join-Path (Split-Path $Sdk) 'mp109-sdk-unpacked'
$null = New-Item -ItemType Directory -Path $Unpacked -Force
Push-Location $Sdk
try {
    & (Join-Path $Tools 'xrCompress.exe') -unpack fsgame.ltx $Unpacked
} finally {
    Pop-Location
}
Get-Item -LiteralPath (Join-Path $Unpacked 'gamemtl.xr')
~~~
