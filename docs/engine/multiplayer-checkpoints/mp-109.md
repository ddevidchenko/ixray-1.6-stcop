# MP-109 two-client ladder test on Windows

Build a small deathmatch map with one ladder and one stalker, then watch the same bot from two game windows on the same PC. This test uses engine commit `6269279ce070ca0d775d37711d49a270e8392b2c`. The Windows build and gameplay checks are pending.

Use PowerShell 7.4 or newer in your Windows repo checkout with the MP-109 changes. Reuse the Visual Studio, x64 CMake, and game assets from your passing W0 run. If the candidate is only on your Mac, [copy it to Windows first](#if-the-commit-is-only-on-your-mac). The first build and asset copy can take a while. Once the runner starts the game, it gives the server two minutes to become ready and the clients three minutes to join.

## 1. Set up the IX-Ray Level Editor workspace

### Set the folder paths

Use IX-Ray’s Level Editor and compilers with the file-system settings from this checkout. To build the arena, you also need editable level objects in `rawdata\objects`. The repo ships an editor axis in that folder. The retail game archives supply compiled game assets. The steps below add a ready-made floor and ladder to your IX-Ray workspace.

From your Windows repo checkout, set the three paths below. Use your original Call of Pripyat installation or the IX-Ray game folder from W0 for `$Original`. Pick new folders for the test game copy (`$GameRoot`) and the editor workspace (`$Sdk`).

~~~powershell
$Candidate = '6269279ce070ca0d775d37711d49a270e8392b2c'
$Original = 'C:\Games\Call of Pripyat'
$GameRoot = 'C:\Games\IXRay-MP109'
$Sdk = 'C:\Games\IXRay-MP109-Editor'
$Map = 'mp109_ladder'
$Runner = '.\scripts\multiplayer\windows\RunCheckpoint.ps1'

git cat-file -e "$Candidate^{commit}"
if ($LASTEXITCODE -ne 0) { throw 'Sync the MP-109 commit into this Windows checkout, then retry.' }
~~~

### Make the game copy

~~~powershell
if (Test-Path -LiteralPath $GameRoot) { throw 'Use a new path for the MP-109 game copy.' }
Copy-Item -LiteralPath $Original -Destination $GameRoot -Recurse -ErrorAction Stop
~~~

If you copied a retail-only installation, add the repo’s IX-Ray CoP game files to the test copy.

~~~powershell
robocopy .\gamedata (Join-Path $GameRoot 'gamedata') /E /XJ /R:0 /W:0 /NFL /NDL /NP
if ($LASTEXITCODE -ge 8) { throw 'Copying the IX-Ray game assets failed.' }
~~~

### Get the editable objects and their game assets

If you only have the original game and the IX-Ray binaries, use the following commands to extract `gamedata` and `rawdata` from the CoP 0.7 download. The download is about 446 MiB. `innoextract` reads the package as an archive and expands about 1.3 GiB of assets. [GSC’s CoP 0.7 package](https://cop.stalker-game.com/product.php?page=news), [innoextract Windows download](https://constexpr.org/innoextract/#download)

~~~powershell
$AssetCache = Join-Path $env:TEMP 'mp109-sdk-assets'
$null = New-Item -ItemType Directory -Path $AssetCache -Force
$AssetArchive = Join-Path $AssetCache 'xray-cop-sdk-setup.exe'
$ExtractorZip = Join-Path $AssetCache 'innoextract-1.9-windows.zip'
$ExtractorFolder = Join-Path $AssetCache 'innoextract'
$AssetOutput = Join-Path $AssetCache 'extracted'
$AssetLog = Join-Path $AssetCache 'extract.log'

Invoke-WebRequest -Uri 'https://files.gsc-game.com/st/xray-cop-sdk-setup.exe' -OutFile $AssetArchive -ErrorAction Stop
Invoke-WebRequest -Uri 'https://constexpr.org/innoextract/files/innoextract-1.9-windows.zip' -OutFile $ExtractorZip -ErrorAction Stop
Expand-Archive -LiteralPath $ExtractorZip -DestinationPath $ExtractorFolder -Force -ErrorAction Stop
$ExtractArgs = @('--extract', '--include', 'app/editors/gamedata', '--include', 'app/editors/rawdata',
    '--output-dir', $AssetOutput, $AssetArchive)
& (Join-Path $ExtractorFolder 'innoextract.exe') @ExtractArgs *> $AssetLog
if ($LASTEXITCODE -ne 0) { throw "CoP asset extraction failed. See $AssetLog." }
$AssetSource = Join-Path $AssetOutput 'app/editors'
~~~

If you already have compatible CoP `gamedata` and an editable `rawdata\objects` library, set `$AssetSource` to their parent directory and skip the downloads. If you want to use your retail archives as the asset source, build `xrCompress.exe` using the tool build below, then [reconstruct a scene from a stock map](w0.md#if-you-only-have-compiled-map-files) using IX-Ray’s unpacker and the external X-Ray scene converter. Use that procedure’s `$Unpacked` folder as the converter’s `$sdk_root$` and then as `$AssetSource`. Check the resulting geometry and materials in the IX-Ray editor before baking.

### Prepare the IX-Ray workspace

Run this from the same checkout. It brings in the objects, textures, and `gamemtl.xr` from the asset source, then adds the repo’s editor resources and file-system settings.

~~~powershell
foreach ($Path in 'gamedata/gamemtl.xr', 'rawdata/objects') {
    if (!(Test-Path -LiteralPath (Join-Path $AssetSource $Path))) {
        throw "Missing $Path under $AssetSource."
    }
}
$null = New-Item -ItemType Directory -Path $Sdk -Force
foreach ($Folder in 'gamedata', 'rawdata') {
    $Destination = Join-Path $Sdk $Folder
    robocopy (Join-Path $AssetSource $Folder) $Destination /E /XJ /R:0 /W:0 /NFL /NDL /NP
    if ($LASTEXITCODE -ge 8) { throw "Could not copy the CoP $Folder to $Sdk." }
    robocopy ".\$Folder" $Destination /E /XJ /R:0 /W:0 /NFL /NDL /NP
    if ($LASTEXITCODE -ge 8) { throw "Could not copy the IX-Ray $Folder to $Sdk." }
}
Copy-Item -LiteralPath '.\fs.ltx', '.\fsfactory.ltx', '.\fsgame.ltx', '.\.xrignore' -Destination $Sdk -Force -ErrorAction Stop
~~~

### Launch IX-Ray Level Editor

Use the `LevelEditor.exe` built from this repo. If your build folder already contains `LevelEditor.exe`, `xrLevelBuilder.exe`, and `xrSE_Factory.dll` together, set `$Tools = 'C:\path\to\bin\RelWithDebInfo'` with its actual path and skip the build block. Otherwise build the tools together.

~~~powershell
cmake -S . -B build/mp109-sdk -A x64 -DIXRAY_EDITORS=ON -DIXRAY_UTILS=ON -DIXRAY_MP=OFF
if ($LASTEXITCODE -ne 0) { throw 'SDK configure failed. Save the terminal output.' }
cmake --build build/mp109-sdk --config RelWithDebInfo --parallel --target LevelEditor xrLevelBuilder xrSE_Factory xrCompress
if ($LASTEXITCODE -ne 0) { throw 'SDK build failed. Save the terminal output.' }
$Tools = (Resolve-Path 'build/mp109-sdk/bin/RelWithDebInfo').Path
~~~

~~~powershell
Start-Process -FilePath (Join-Path $Tools 'LevelEditor.exe') -WorkingDirectory $Sdk -ArgumentList '-fsltx fs.ltx'
~~~

Open **Objects → Library Editor**. In the GSC library, preview `statics\concrete_slab\plita_celka` and `statics\fake_object\fake_ladders`. The slab can serve as a flat landing. The ladder uses `materials\fake_ladders`, which has **Climable** set. If you supplied your own library, preview your floor and ladder objects. Check that **Spawn → stalkers → stalker** is available before starting the map.

If the library is empty or the editor reports missing assets, confirm it was launched with `$Sdk` as the working directory and check `$Sdk\logs`. If you need other geometry, you can [unpack and import a stock map](w0.md#if-you-only-have-compiled-map-files).

## 2. Build one ladder arena

1. In **Scene Properties**, set **Build options → Level path** to `mp109_ladder` and **Map version** to `1.0`. Enable **deathmatch** under **Game Type**.
2. Add a lower floor, a raised platform, and one tall ladder. In **Objects → Library Editor**, set the ladder face’s **Game Mtl** to a material with **Flags → Climable**. Leave the face and both landings clear. The tall ladder gives you time to reconnect during a climb. In an empty scene, add an outdoor light and use **Sector → Create Default**.
3. Add two `$rpoint` markers on clear lower ground several metres apart. For both, choose **Actor Spawn**, **Team 0**, and **deathmatch**. Add one **Spawn → stalkers → stalker** on clear lower ground and enable **deathmatch** for it.
4. Select the floor and platform objects. Use **Snap List → Make List From Selected**. In **AI Map**, place a seed on each floor and click **Generate Full**. Check that each landing has a patch of connected nodes. Keep the floors disconnected so the ladder is the bot’s only route between them.
5. Save the scene. Choose **Compile → Make → Make All**. In `$Sdk\gamedata\levels\mp109_ladder`, check for `build.prj`, `build.aimap`, `level.game`, and `level.spawn`. **Make Game** exports the player spawns, ladder, and stalker. **Make AI-Map (25 bit)** exports the editor grid.

Launch the compiler from the same PowerShell window.

~~~powershell
Start-Process -FilePath (Join-Path $Tools 'xrLevelBuilder.exe') -WorkingDirectory $Sdk -ArgumentList '-fsltx fsgame.ltx'
~~~

Select only `mp109_ladder` in the compiler. Enable **Lighting Compiler** and click **Run Compiler**. When it finishes, switch off **Lighting Compiler**, enable **AI Compiler**, and check **AI Compiler ai.level** and **Verify**. Leave **Draft AI-Map** and **AI Compiler all.spawn** off. Click **Run Compiler** again. Check that `level.ai` and `level.cform` are in the same folder as `level.spawn`.

## 3. Package the map and run the startup check

Use the exact `gamemtl.xr` the SDK used for the bake. If it came from an archive, [extract it first](#if-the-material-file-is-still-in-an-archive). This block copies it into the test game so the packer and server load the same file.

~~~powershell
$Materials = Join-Path $Sdk 'gamedata\gamemtl.xr'
if (!(Test-Path -LiteralPath $Materials -PathType Leaf)) { throw 'Set $Materials to the gamemtl.xr used by the SDK.' }
$null = New-Item -ItemType Directory -Path (Join-Path $GameRoot 'gamedata') -Force
Copy-Item -LiteralPath $Materials -Destination (Join-Path $GameRoot 'gamedata\gamemtl.xr') -ErrorAction Stop

cmake -S src/test/multiplayer/portable -B build/mp109-nav -A x64
if ($LASTEXITCODE -ne 0) { throw 'Navigation tool configure failed.' }
cmake --build build/mp109-nav --config RelWithDebInfo --target ArenaNavPack
if ($LASTEXITCODE -ne 0) { throw 'Navigation tool build failed.' }
$Packer = (Resolve-Path 'build/mp109-nav/RelWithDebInfo/ArenaNavPack.exe').Path
$Cooked = @{ EditorRoot = $Sdk; GameDataRoot = $GameRoot; NavigationPacker = $Packer; Map = $Map; MapVersion = '1.0' }
$Fixture = & .\scripts\multiplayer\windows\PrepareW1Fixture.ps1 @Cooked -AutoLadders
$LadderReport = Join-Path (Split-Path $Fixture) 'w1-ladders.txt'
Get-Content -LiteralPath $LadderReport
if (!(Select-String -LiteralPath $LadderReport -Pattern '^ladder candidates=1 directed links=2$' -Quiet)) {
    throw 'Expected one ladder and two directions. Save w1-ladders.txt and check the reported reason.'
}
& $Runner -Revision $Candidate -GameDataRoot $GameRoot -Map $Map -Mode BaselineRuntime -RuntimeCase StalkerNavigation
~~~

Write down the two numbers after `nodes=` in `w1-ladders.txt`. The lower node comes first. If you rebake, move the previous staged map folder out of `gamedata\levels` before staging the new one. Keep the old report with it.

The runner builds `xrServerCLI.exe` and `xrEngine.exe` in `RelWithDebInfo` with `IXRAY_MP=ON` and `IXRAY_MP_SQL=OFF`. It starts and closes its own server and two clients. Expect `w1_navigation_passed`. Copy the full path printed after `W0 report`. If the runner fails, send that `report.json` and its entire neighbouring `logs` folder. If the build hits a path-length error, keep the failure logs and rerun the same command with `-WorkspaceRoot` set to a short folder on an existing drive. The startup check covers joins and navigation readiness. The next steps check the stalker.

## 4. Start the interactive server and two clients

Open two PowerShell windows. In **both**, paste this block with your W1 report path.

~~~powershell
$W1Report = 'C:\path\from\W0-report\report.json'
$Run = Get-Content -LiteralPath $W1Report -Raw | ConvertFrom-Json
if ($Run.status -ne 'w1_navigation_passed' -or $Run.actualRevision -ne '6269279ce070ca0d775d37711d49a270e8392b2c') {
    throw 'Use the passing W1 report for the MP-109 candidate.'
}
$Runtime = Join-Path $Run.workspaceDirectory 'runtime'
$Bin = Join-Path $Run.buildDirectory "bin/$($Run.configuration)"
$Map = $Run.runtime.map
$Port = $Run.runtime.port
$Tag = 'mp109'
~~~

In the **first** window, run this block. Keep the printed `start server(...) client(...)` line for the reload test. Wait for `Arena navigation` with `links=2` and `DM ready: role=server`.

~~~powershell
$Server = "server($Map/deathmatch/maxplayers=32/portsv=$Port/public=0/bots=1)"
$InternalClient = "client(localhost/port=$Port/name=MP109Server)"
Write-Host "start $Server $InternalClient"
Push-Location $Runtime
try {
    $null = New-Item -ItemType Directory -Path "$Tag-server" -ErrorAction Stop
    & (Join-Path $Bin 'xrServerCLI.exe') -overlaypath "$Tag-server" -nosound -mp_route_trace -start $Server $InternalClient
} finally {
    Pop-Location
}
~~~

In the **second** window, run this block. It prints the exact reconnect command for each client. Arrange the two game windows side by side. Press **Space** in each to enter play. The backtick key opens the game console.

~~~powershell
foreach ($Index in 1, 2) {
    $Overlay = "$Tag-client-$Index"
    $Data = New-Item -ItemType Directory -Path (Join-Path $Runtime $Overlay) -ErrorAction Stop
    'rs_fullscreen 0' | Set-Content -LiteralPath (Join-Path $Data.FullName 'user.ltx') -Encoding ascii
    $Connect = "client(127.0.0.1/port=$Port/name=MP109Client$Index)"
    Start-Process -FilePath (Join-Path $Bin 'xrEngine.exe') -WorkingDirectory $Runtime -ArgumentList @(
        '-overlaypath', $Overlay, '-nosound', '-r2', '-mp_route_trace', '-start', $Connect
    )
    Write-Host "Client $Index reconnect command is start $Connect"
}
~~~

For another attempt using the same W1 report, use a new `$Tag` in both windows, such as `mp109-retry`. If the port was taken after W1 exited, set `$Port` to the same available local UDP port in both windows.

## 5. Move the bot and record what you see

Paste these lines one at a time into the **dedicated server console**. In the second line, replace `12` and `84` with your lower and upper node IDs. The first line prints the bot ID. If it reports no live stalker, save the dedicated log and check the stalker spawn and deathmatch flag in the editor.

~~~text
run_string mp109_bot=nil; for i=0,65534 do local n=level.object_by_id(i); if n and n:section()=="stalker" and n:alive() then mp109_bot=i; break end end; assert(mp109_bot,"MP109 no live stalker"); log1("MP109 stalker="..mp109_bot)
run_string mp109_lower=12; mp109_upper=84; assert(level.valid_vertex_id(mp109_lower) and level.valid_vertex_id(mp109_upper))
run_string function mp109_go(v) local n=assert(level.object_by_id(mp109_bot)); assert(n:alive()); if not n:get_script() then n:script(true,"mp109") end; assert(n:get_script_name()=="mp109"); n:reset_action_queue(); log1("MP109 goal="..v.." stalker="..mp109_bot); action(n,move(move.standing,move.walk,move.line,level.vertex_position(v)),cond(cond.move_end)) end
~~~

Give the bot the lower goal first. Once it arrives, give it the upper goal. After it dismounts at the top, send it back down.

~~~text
run_string mp109_go(mp109_lower)
run_string mp109_go(mp109_upper)
run_string mp109_go(mp109_lower)
~~~

Record both windows together or save a clip from each. Write `pass`, `fail`, or `skip` for each check in `observations.txt`. Add a short note for anything that failed or was skipped.

| Check | What to do and watch for |
| --- | --- |
| Up and down | Watch one full trip each way. The bot faces the ladder, mounts, moves its hands and feet with the climb, and returns to a normal pose on the correct floor. Both client logs should show `up` or `down` and then `ground` for the same stalker. |
| Blocked exit | Move client 2 to the upper floor and stand in the ladder exit. Send the bot up while client 1 watches. The pose should hold when the body stops. If the dedicated log reports `failed`, both clients should leave the climb pose. Move client 2 clear and watch the next attempt. |
| Late join | On client 2 enter `disconnect`. Send the bot to the other floor. While client 1 sees it climbing, paste client 2’s printed reconnect command into its game console. The bot should first appear in its current position and phase. Repeat in the other direction. If the climb ends before client 2 sees it, retry or mark the case skipped. |
| Death during a climb | While both clients are watching a climb, paste the kill command below into the dedicated console. Both clients should switch from climb to death. |
| Reload during a climb | Reload after the death check to get a live bot. Start another climb and reload while it is on the ladder. Reconnect both clients, paste the three setup lines again, and verify that the new bot starts normally and can climb. The dedicated log should show the old navigation generation closing and a new one becoming ready. |

Kill the selected bot from the dedicated server console.

~~~text
run_string local n=assert(level.object_by_id(mp109_bot)); n:kill(n)
~~~

To reload, enter `disconnect` in the **dedicated** console, then paste the `start server(...) client(...)` line printed in the first PowerShell window. After `DM ready: role=server`, use the respective reconnect commands in the two game consoles. When finished, type `quit` in each game console and the dedicated console so all three logs close.

## 6. Send back the results

From the second PowerShell window, gather the reports and logs.

~~~powershell
$Evidence = Join-Path (Split-Path $W1Report) "$Tag-evidence"
$null = New-Item -ItemType Directory -Path $Evidence -ErrorAction Stop
Copy-Item -LiteralPath $W1Report -Destination (Join-Path $Evidence 'w1-report.json')
Copy-Item -LiteralPath (Join-Path (Split-Path $W1Report) 'logs') -Destination (Join-Path $Evidence 'w1-logs') -Recurse
$StagedMap = Join-Path $Runtime "gamedata/levels/$Map"
foreach ($Name in 'w1-fixture.json', 'w1-ladders.txt') {
    Copy-Item -LiteralPath (Join-Path $StagedMap $Name) -Destination $Evidence
}
foreach ($Name in "$Tag-server", "$Tag-client-1", "$Tag-client-2") {
    $Logs = Join-Path $Runtime "$Name/logs"
    if (Test-Path -LiteralPath $Logs) {
        Copy-Item -LiteralPath $Logs -Destination (Join-Path $Evidence $Name) -Recurse
    } else {
        Write-Warning "No log directory at $Logs. Note which process did not write a log."
    }
}
$Evidence
~~~

Add `observations.txt` and the recordings to that folder. The important gameplay logs are the **interactive dedicated log and both interactive client logs**. Include the full logs so the startup, `clip=missing` lines if any, and both map generations are visible. If asset extraction failed, send the PowerShell error and `$env:TEMP\mp109-sdk-assets\extract.log` if present. If the editor or compiler failed, send its logs from `$Sdk\logs` or `$Sdk\_appdata_ixray_\logs`, respectively.

Send the entire evidence folder or zip it with this command.

~~~powershell
Compress-Archive -LiteralPath $Evidence -DestinationPath "$Evidence.zip"
~~~

W1 keeps its build and runtime under `<checkout>\build\w0\<id>`. The report and evidence zip live under `<checkout>\build\test-results\multiplayer\<commit>\<run-id>`. You can reclaim the build and runtime space after saving the evidence.

## If the commit is only on your Mac

In the Mac repo, make a Git bundle of the commits since the shared `origin/default`. Copy the bundle to your Windows PC.

~~~bash
git bundle create /tmp/ixray-mp109.bundle origin/default..default
~~~

In your existing Windows checkout, replace the bundle path below. The import needs the shared base revision in that checkout. It creates a separate validation worktree.

~~~powershell
git fetch 'C:\path\to\ixray-mp109.bundle' refs/heads/default:refs/heads/mp109-candidate
if ($LASTEXITCODE -ne 0) { throw 'Import failed. Check the bundle path and shared base revision.' }
git worktree add --detach build/mp109-src 6269279ce070ca0d775d37711d49a270e8392b2c
if ($LASTEXITCODE -ne 0) { throw 'Could not create the validation worktree.' }
Set-Location build/mp109-src
~~~

Run step 1 from this worktree. If you already have the candidate in your Windows checkout, you can use that checkout directly.

## If the material file is still in an archive

Use the SDK file-system configuration to unpack to a scratch folder. In step 3, set `$Materials` to the extracted file shown below.

~~~powershell
$Unpacked = Join-Path (Split-Path $Sdk) 'mp109-sdk-unpacked'
$null = New-Item -ItemType Directory -Path $Unpacked -Force
Push-Location $Sdk
try {
    & (Join-Path $Tools 'xrCompress.exe') -unpack fsgame.ltx $Unpacked
} finally {
    Pop-Location
}
Get-Item -LiteralPath (Join-Path $Unpacked 'gamemtl.xr')
~~~
