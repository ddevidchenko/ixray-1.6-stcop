# W0 Windows multiplayer check

## Before you start

Use your existing Windows build setup and open PowerShell 7.4 or newer from the W0 candidate checkout. Keep `git`, `cmake`, and `ctest` on `PATH`. W0 uses `cmake -B <build-dir> -A x64` and lets CMake select the generator. Use CMake 3.26 or newer with Visual Studio 2022, or CMake 4.2 or newer with Visual Studio 2026. [Project requirements](../../../.github/README.md#requirements), [CMake’s Visual Studio 2026 generator](https://cmake.org/cmake/help/v4.2/generator/Visual%20Studio%2018%202026.html)

For the match, use a Call of Pripyat installation with the IX-Ray assets and an installed DM map. Use the lowercase map name from `gamedata/levels/` or from its matching `.db` or `.xdb` archive in `mp/`. Replace both examples below with your local values.

## Run the two-client check

```powershell
$Runner = '.\scripts\multiplayer\windows\RunCheckpoint.ps1'
$W0 = @{ Revision = (git rev-parse HEAD) }
$Game = @{ GameDataRoot = 'C:\Games\IXRay'; Map = 'mp_atp' }
& $Runner @W0 @Game -Mode BaselineRuntime -RuntimeCase Observe
```

W0 writes each run under `<checkout>\build\test-results\multiplayer\<sha>\<run-id>`. The isolated test build lives below that run’s `source\build\` directory. The `logs\` directory and `report.json` sit beside `source\`. To override the location, pass `-ResultsRoot` with a directory path on an existing drive.

The runner builds the exact commit with multiplayer enabled, stages a copy of the game data, and starts a dedicated server and two windowed clients. Allow time for a cold build and asset copy. Once both clients join, follow the terminal’s ten-minute checklist for firing, death and scoring, respawn, disconnect, and reconnect. The default game controls use backtick for the console and Tab for the scoreboard. Leave both client windows open and use the reconnect command printed by the runner.

After each action, return to PowerShell and press `Y` if you observed the expected result, `N` if it failed, or `S` to skip it. Press `Q` to finish early and keep your results. The runner closes its own processes and prints the path to `report.json`. Return that file with `logs/` and any notes you add to `observation-notes.txt`. Keep `report.json` and the logs before deleting the run’s `source/` and `runtime/` directories to recover space.

`runtime.startupPassed` records the automated join and writable-path checks. `runtime_observation_passed` requires confirmation of every gameplay action. Failed and incomplete observations retain their individual results in the report. Windows execution is pending.

## Additional checks

Use the same variables from the main command. Run `Portable` for the unit test and deliberate failure check. Run `ListenerFailure` to verify that the server reports a failure when its UDP port is occupied.

```powershell
& $Runner @W0 -Mode Portable
& $Runner @W0 @Game -Mode BaselineRuntime -RuntimeCase ListenerFailure
```

Expect `portable_passed` and `listener_failure_observed`. For build diagnostics alone, use `& $Runner @W0 -Mode BaselineBuild`. For unattended startup checks, use `& $Runner @W0 @Game -Mode BaselineRuntime -RuntimeCase Join` and expect `runtime_smoke_passed`.

For the before-and-after record, use the same runner checkout, map, and assets with the test-only revision. The listener check should report an internal client attempt after the bind failure if it reproduces the original defect. The join check looks for the readiness marker introduced by the fix. Keep a build error, crash, missing map, or timeout distinct from a reproduced defect.

```powershell
$TestOnly = $W0.Clone()
$TestOnly.Revision = git rev-parse f103ef3e9
& $Runner @TestOnly @Game -Mode BaselineRuntime -RuntimeCase ListenerFailure
& $Runner @TestOnly @Game -Mode BaselineRuntime -RuntimeCase Join
```

On macOS, `pwsh -NoProfile -File src/test/multiplayer/checkpoints/TestW0Evidence.ps1` checks runner decisions without starting the engine.
